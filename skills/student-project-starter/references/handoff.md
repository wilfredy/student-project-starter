# Teach the student how to get and use the project

The final response and project README should let a beginner reproduce the successful local run. Use actual OS, package manager, paths, and scripts.

1. **Where is it?** Give the exact folder and key files; explain opening the folder in their editor. If downloads are supported, give a clean source archive/link. If it is only local, say so. Never invent a GitHub repo.
2. **How do I get it on another computer?** Explain copying/downloading source or cloning an existing authorized repo. Include lockfiles/examples; exclude real env files, tokens, dependency folders, caches, personal data, and n8n volumes. Recreate private settings there. Do not create/push a remote repo merely to give these instructions.
3. **How do I run it?** Give exact directory/install/start commands, where missing settings go, and the browser address. Explain Ctrl+C and restarting. With a compatible lockfile, use the package manager's reproducible install command for a fresh checkout.
4. **How do I see mobile?** Explain Expo Go versus a development build for selected features, QR/device or simulator steps, and reachable phone/computer connections. Identify untested device steps.
5. **How is it organized?** Explain the main screen/page, backend route, data client/schema, and automation file that actually exist. Point to one simple edit and its visible result.
6. **What works?** Separate verified checks, local demo, configured services, and unverified integrations. Give the next required action by name without values.
7. **How do I publish later?** Explain the selected host/store path and accounts needed. Separate local preview from public deployment; carry out publication only within authorization.

End with a small exercise such as changing the home-screen title and reloading. Offer a walkthrough without turning the handoff into an unrelated course.
